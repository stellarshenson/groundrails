## Upgrade notes

- 1.0.36 adds the REQUIRED config fields `bm25_min_claim_tokens`, `nli_entailment_min` and `nli_contradiction_min`. A project/user override `config_document_processing.yaml` written against <=1.0.35 raises `ConfigError: missing required fields: [...]` until the keys are added - deliberate (the config contract is fail-loud, no hardcoded defaults); add `bm25_min_claim_tokens: 4`, `nli_entailment_min: 0.5` and `nli_contradiction_min: 0.5` to the override
- 1.0.36 adds the `nli` match_type: an NLI-driven confirm whose lexical layers all sit below their own thresholds is now labelled `nli` instead of borrowing a lexical layer's name. Consumers switching on match_type should treat `nli` as grounded (the `GroundingMatch.grounded` property already does); its headline score is the entailment probability, its location/passage fall back to the premise's origin layer, and it is verification-flagged when no lexical layer co-supports
- 1.0.36 removes the dead CLI helpers `_build_semantic_grounder` / `_build_nli_grounder` / `_nli_calibrated_verdict` (no call sites since the semantic switch moved to `joint.py`; one read a phantom `cfg.nli_model` field via getattr-default, defeating the fail-loud config contract)

## Known limitations (not defects)

- BM25 layer is absent on tiny corpora (2-3 passages): every Okapi score can go negative and the layer returns no hit. A recall-argmax fallback was tried and reverted - `bm25_score` feeds the calibrated features and resurrecting the layer shifts the pinned golden distribution. Revisit only together with a recalibration
- `_looks_like_claim` passes 4+-word noun fragments (needs POS, out of regex-tier scope); its irregular-past whitelist is CLOSED - the common trend, invariant-past and prefixed forms are listed (rounds 7-8), but uncommon irregulars outside it still drop a claim silently, and bold-line pseudo-headings (`**References**`) are not treated as section headings (their entries get extracted and simply fail grounding - fail-safe)
- The exact layer is a word-bounded SUBSTRING match: a claim quoted verbatim inside a sentence that then negates it ("...asserted that the cluster has 42 nodes. This assertion is false...") still grounds as `exact`. Accepted tradeoff of the DEF-9 exact-wins policy; a negation-cue check needs NLI over the surrounding window - and note NO SHIPPED PATH presents an exact confirm to NLI (joint early-returns exact before the cascade; the CLI builds no NLI grounder) - only an API caller passing `nli_grounder` gets the windowed premise. The numeric side of this window IS covered by WI#6 reason (d'), including the value restated beside the conflict (round 8). Pinned by `TestKnownLimitations::test_verbatim_claim_inside_negating_evidence_still_grounds`
- A sub-floor claim (under `bm25_min_claim_tokens` unique tokens) that is NOT verbatim in the source and clears neither the fuzzy nor the semantic threshold is always refused on the lexical tier, whatever the head probability - a real behaviour change vs <=1.0.35 for API users grounding short phrases, in the fail-safe direction. Pinned by `TestKnownLimitations::test_subfloor_paraphrase_cannot_confirm_on_lexical_tier`
- Numeric contradiction detection compares only within the same (unit, context-word) key: paraphrase that shifts the context word ("rose 40% overall" vs "rose by 50% in the quarter") gives divergent keys and the value conflict is not flagged. Deliberate precision-over-recall trade from the DEF-5 fix - the pre-fix behaviour pooled all same-unit numbers and flooded false CONTRADICTED. Pinned by `TestKnownLimitations::test_divergent_numeric_contexts_skip_comparison`
- The inverse collision also exists: numbers about DISJOINT subjects that share a trailing context word ("Zebra populations declined 25% in the audited quarter" vs "Revenue grew 40% in the audited quarter" both key `('%','audited')`) fire a spurious mismatch. Subject/entity linking is out of the deterministic tier's scope. Pinned by `TestKnownLimitations::test_shared_trailing_context_can_collide_across_subjects`
- The round-8 conflict-beside-agreement flag (WI#6 reason (d)/(d'), `_restated_numeric_conflict`) fires on ANY differing value under a shared (unit, context-word) key, so it cannot tell a genuine competitor ("42 confirmed, 12 also present") from benign SAME-context elaboration ("400 families in the main arm and 250 families in the control") - both raise `verification_needed`. Distinguishing conflict from elaboration is semantic, out of the deterministic tier's reach; the flag is verification-only (the verdict is never touched) and errs fail-safe, and a different context word ("250 in the pilot cohort") already avoids the collision. Pinned by `TestKnownLimitations::test_numeric_neighbor_over_flags_same_context_elaboration`
- The NLI cascade policy (confident entailment confirms, confident contradiction contradicts, everything else falls through) is stub-tested for control flow only - the NLI model is not cached in the dev environment, so no real-model delta run over the fixtures exists yet. Run one and record the false-confirm/false-refusal deltas here before trusting the policy on production NLI output
- The NLI verdict is first-class only in the deterministic cascade. The calibrated head consumes NLI as `nli_entail`/`nli_contra` features; the trained lexical head's frozen feature set carries no NLI term at all, so under the shipped default config (`mode: lexical` + manifolds) a caller passing `nli_grounder` gets contradiction-guard-only NLI. Feeding entailment into the lexical head is a recalibration item
- The joint tier folds the cascade's bge-m3 cosine into `semantic_score` but gates the DEF-4 floor against `cfg.semantic_threshold` (0.6, tuned on the legacy embedding space) while the cascade's native gate is 0.493-0.739; and the joint head threshold was fit before the floor post-filter existed. Both want a re-measurement on the joint calibration set at the next recalibration
- The DEF-8 speedup ratios divide by a 120.9 ms/claim baseline measured on the pre-fix tree at commit `9d5f4bd` with the same claim set and warm-batch loop as `scripts/bench_grounding.py`; the baseline is not re-derivable from the current tree alone
- The golden equivalence set is a migration pin, not a drift detector for new populations (no signed numbers, no sub-floor claims, no markdown sections, single-passage sources; non-English items skip offline). New-population behaviour is pinned instead by `TestKnownLimitations` + `test_defect_regressions.py`
